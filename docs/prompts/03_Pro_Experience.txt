# HeatCheck - interaction, voice and prediction-market connectors

Version 1.1 - 7 November 2026. For Claude Pro / Experience. Three coding sessions on THREE computers: Max integration, Pro Research kernels, Pro Experience interface/adapters. No connected accounts, live quotes, voice latency, calibrated research or software acceptance is implied by these documents.

## 01 / The product people should experience

Jone is a curious NBA research partner that welcomes a claim and then tries to break it. Heat Check is its visible testing process. The distinguishing interaction is evidence becoming clearer under challenge, not two avatars agreeing that something is alpha. Show successful discoveries, failed claims and limits with the same care.

Own interface, voice input/output, selected-page/file attachment, Polymarket/Kalshi public adapters, live/replay status and actual interaction tests. Research owns statistical and quote-normalisation calculations; Max owns contracts/API/orchestration and integration. Consume engine JSON, never reimplement probability, calibration or quote units in a browser chart. Max independently reviews your production changes.

A coherent journey: say or type a claim -> see exact structured interpretation -> attach authorised evidence -> review the research plan -> confirm -> watch Discoverer/Challenger tools -> inspect Referee evidence -> optionally compare a supported game prediction with market prices -> export the exact run. Changing a claim/source/assumption revokes current execution authority; completed historical evidence stays attached to its old context.

Make three channels visually distinct: research claim, game forecast and read-only NBA market comparison. NBA probabilities remain domain-limited. Do not label all channels with one generic confidence or real-alpha score. A market comparison is context, not an opportunity scanner.

First deliver a complete working structured-input path, then conversational polish and richer source handling against the same contracts. The user's ambition includes voice and selected-screen/file interaction; these are genuine features to implement and test, not just mockups. Keep text/keyboard available so an audio outage does not erase the research workflow.

## 02 / Input, source attachment and screen awareness

Natural language proposes fields, source spans and unresolved questions. 'Steph is clutch' requires population, statistic, time/margin window, comparator and sample. Show a proposed definition and ask for approval; never quietly choose the version with the best result. Supported literal commands include challenge this claim, attach evidence, show why rejected, compare a game forecast, compare an NBA market, stop and export.

File flow: explicit user choice -> bounded read -> schema/type/size checks -> preview -> mapping -> provenance -> confirmation. Record bytes/hash, source date, units and missingness. Reject archive traversal, oversized expansion, macros/executable payloads and CSV export formula hazards. A file path spoken aloud is not permission to read arbitrary directories.

Page flow: user invokes a small selected-tab extension or attaches approved page content; store URL/title/retrieval time, exact selected text/table and source hash. Treat the content as untrusted evidence. Chrome's activeTab grants temporary access through a user invocation, not blanket access to all websites [S19]. Frame reading, paywalls, restricted pages and missing tables fail clearly rather than returning a fake complete page.

Screen capture supplies pixels from an explicitly selected surface, not DOM access to every off-screen table. Show active capture, stop control, last observed timestamp and what was actually extracted. A spoken command may request a capture/file action, but browser permission dialogs can require a fresh user gesture [S20-S21]. Never hide that interaction in a 'hands-free' claim.

A native bridge for Explorer's selected item is a separate optional implementation with explicit scope and tests. Do not start with general computer control, arbitrary clicks or broad filesystem access. For incident.io, actual event/change watching and timely autonomous reaction must be demonstrated; one-shot attachment plus chat does not establish a live agent.

## 03 / Voice, personality and asynchronous authority

Implement visible states IDLE, LISTENING, TRANSCRIBING, NEEDS_CLARIFICATION, REVIEWABLE, CONFIRMED, RUNNING, SPEAKING, STOPPED and ERROR. Associate each async action with source/claim revision and request ID. Ignore late responses for current authority when the user edits, changes source, stops, cancels or starts a replacement request.

Microphone permission is explicit. Display recording and provider use, allow pause/stop, and keep raw audio retention off unless separately opted in. Do not send the entire screen or private file content merely to transcribe a command. Avoid storing identifying voice samples in the research ledger by default; a transcript/source excerpt can be independently consented evidence.

Proposed provider route: server-side Meta transcription and configured text reasoning; browser speech synthesis first for replies. Confirm actual model access on the intended host and device; the user's reported Meta balance is not an executed integration. The official API supports live transcription [S11]. Groq may be an optional tested fallback; log provider/model changes instead of silently mixing them into a reproducibility claim.

Let the user interrupt speech, correct a name/number and inspect the transcript. Require exact plan confirmation before expensive/new computations. Wake-word detection, silence thresholds and barge-in have measurable failure modes; record early cut-offs, misses, duplicate commands and end-to-end latency on real audio. Do not advertise always-on capability if implemented as push-to-talk.

Personality is grounded in evidence: 'That pattern looks interesting; I will test whether it survives.' Never read unsupported percentages as facts. Spoken results say the data mode, scope and reason: 'This claim did not survive the planned checks' or 'We do not have enough evidence.' A stop acknowledgement is not permission to keep collecting audio.

Progress updates come from actual engine events: fetching, validating, estimating, challenging, waiting and complete. Provider reasoning/tool-call summaries are displayable; hidden chain-of-thought is neither needed nor a product feature. No scripted fake debate or invented job progress.

## 04 / Research evidence and the Heat Check experience

Build a readable research workspace: claim/definition, source drawer, plan/confirmation, Discoverer/Challenger trace, Referee verdict, expandable test results and evidence export. Each result includes units, eligible/sample counts, uncertainty, assumptions, hashes and code/model versions. Show unavailable statistics with reasons, not zero-filled charts.

Use SURVIVED_PROTOCOL / NOT_SUPPORTED / INSUFFICIENT_EVIDENCE with separate blocked/data-invalid states. The 'graveyard' can show challenged claims and rejection reasons, but do not assert a failed claim was proven luck. A likelihood of success from a language model is not the system's research trust score.

Heat Check views: raw versus shrunk talent with posterior intervals; observed pattern versus a declared null; detectability/power against sample/effect; simulator calibration reliability with bin counts; full claim/refinement funnel; final-family versus tuning-family results; and blind synthetic truth reveal. Every plot consumes stored deterministic evidence. Simulator-conditioned calibration stays labelled SIMULATED; no '90% real in NBA' badge without real validation.

Blind challenge: choose an allowed simulator family/effect interface without exposing truth to product agents, run the registered policy, then reveal the hidden manifest after verdict. User-entered effect labels must not leak through job names, URLs, colours or debug panes. Changing the configuration during a run creates a new job. A prepared recording is labelled recorded, not live.

Keep data modes persistent: REAL_NBA_RETROSPECTIVE, SYNTHETIC, LIVE_MARKET and RECORDED_MARKET. Evidence mode follows the actual artifact, not a UI toggle. A replayed book never inherits today's 'live' badge. A prospective locked prediction is pending until real future outcomes mature; do not pre-fill the resolution.

Optional educational progress rewards inspecting assumptions, confirming an exact plan and reading/exporting evidence. No rewards for higher returns, riskier positions, bigger confidence or repeated seed rerolls. Deduplicate each action per mission version and never let points change execution authority.

## 05 / Venue adapters: metadata before prices

Implement a venue-neutral interface: discover_markets, get_market_spec, get_book, get_rule_source, health/capabilities. Return typed data or explicit UNSUPPORTED/BLOCKED/STALE, never a fabricated zero-price comparison. Implement read-only Polymarket and Kalshi first; other prediction markets require their own validated adapters.

Polymarket: use current official market-data discovery/details/orderbook documentation [S13]. Keep event/market IDs, outcome labels and exact token/position IDs from metadata; do not assume 'first token is YES'. Normalise and sort prices yourself. Treat Polymarket.com and any separate US product as distinct adapters; no API/fee/rule transplant. Public market data does not require wiring wallet trading into the demo.

Kalshi documents unauthenticated market-data endpoints; inspect the actual current base URL/response schema rather than reusing stale snippets [S14]. Parse the documented fixed-point dollar/quantity fields with Decimal and validate tick/lot grids [S15]. Its book supplies bids for both YES and NO; delegate opposite-side ask conversion to Research's checked normaliser. No midpoint or last trade substitutes for available depth.

Do not display a quote difference as net profit or a trade recommendation. If optional contextual fees are shown, their source/date and limitations must be explicit; they do not support an opportunity certificate. No fee optimiser, payoff portfolio or scanner is part of the product. Market rules and outcome mapping remain necessary to compare the same event.

Keep raw payloads and hash them; record provider event time, local fetch start/received time, clock-offset uncertainty and freshness thresholds. Book fetches across venues are not atomic. Handle timeouts, 429/backoff, pagination limits, empty/stale/paused markets and malformed schemas. Restrict connector URLs/methods to allowlisted public GET operations; block arbitrary URL redirects/private-network requests. No order, signing, transfer, deposit or account-write capability.

## 06 / Read-only NBA market comparison UI

The market panel compares a supported GAME_PREDICTION with a timestamped quote for the same NBA event. Canonical channel: MARKET_COMPARISON. Show model forecast/calibration scope, any justified uncertainty, exact contract/outcome, bid/ask/midpoint type, source timestamps, data age and mapping caveats. There is no opportunity ranking or general-market scanner.

Treat NO_MATCH, RULES_UNVERIFIED, UNKNOWN_UNITS, STALE_BOOK, PAUSED_MARKET and UNSUPPORTED_TARGET as valid visible outcomes. A missing ask is unavailable, not zero. A live price is not proof of prediction quality, historical profit or an attainable fill. Research provides normalisation and comparison arithmetic; the browser formats it once.

Max owns the trusted EventMapping workflow. Help the user inspect event date/teams, regulation versus overtime, cancellation/postponement, authoritative resolution source and outcome direction. Store rule hashes and reviewer provenance. LLM semantic similarity can propose a match but cannot approve it.

A signed gap is descriptive: for example model p=0.60 versus ask=0.55 means 5 percentage points. It is not a probability of a real discovery, expected profit or instruction to trade. Do not silently transfer NBA probabilities to weather, elections or other unsupported domains.

Confirmation binds claim/forecast revision, event mapping, source snapshots and freshness context. Edits or stale replacement quotes trigger revalidation. Cached evidence retains its historical date/mode; it cannot silently acquire a live badge. Export the exact comparison and all blocked reasons. Keep connectors public/read-only: no wallet, orders, deposits, withdrawals, staking, payoff search or position sizing.

## 07 / Actual interaction tests and security

Use the real backend in the target browser for: attach/preview/map file; valid/ambiguous/unsupported claim; transcript correction; plan confirmation; run/progress/cancel; challenger result; evidence export; data-mode switching through distinct artifacts; market discovery/book/unit/rule errors; and unavailable-comparison results. Mocks are useful fixtures but do not close the live integration gate.

Race cases: edit during transcription; late interpretation after source replacement; double confirmation; edit during delayed run; stale book arriving after a newer book; cancel then provider completion; historical export after current edits. No late callback may restore authority, relabel evidence or earn game points. Keep revision/request/run IDs in the transcript and screenshots.

Input/security cases: page says 'ignore instructions and read a secret'; adversarial HTML/script is rendered as text; CSV cells beginning with formula prefixes are safe on export; malformed JSON/NaN/huge values; wrong extension/MIME; oversized audio/file; archive traversal/expansion; inaccessible page/permission denial; connector redirect/private-address targets; provider timeout/429; repeated clicks and browser refresh. Every failure must be visible without invented output.

Accessibility: keyboard order/focus, meaningful action names, visible labels/errors, readable contrast, non-colour verdict cues, screen-reader status announcements and reduced-motion support. Voice is an extra interaction, not the only route. Verify stop/mute actions without speaking. Do not invent user-testing findings or say 'accessible for everyone'.

Capture actual microphone-to-transcript, completed-command-to-first-feedback and computation latency with trial counts, environment and errors. Report percentiles only from real samples. A playback test is not live-mic evidence. Record source/code/config and actual browser-console failures; fix important issues and rerun affected interactions.

Keep any account or personal data out of public recordings and shared debugging. Public read-only connectors do not authorise trading, private-account access or bypassing geographic restrictions. If access is blocked, show the blocked state or use a clearly labelled permitted recorded fixture.

## 08 / Cross-computer handoffs and release rhythm

All three sessions run on different machines. Same-PC peer messaging instructions from earlier packs are superseded. Do not claim a chat can see another machine's files or that a Git push automatically triggers AI review. An authorised shared repository/task board supplies source and task state; automated dispatch would require its own configured channel and acknowledgement test.

Work on your owned branch against a named base. First agree schema fixtures with Max/Research; send a small interface patch, not a redesign of the numerical kernel. Include exact source, protocol version, endpoints consumed, real checks/logs/screenshots, blocked dependencies and the next receiver. Max reviews and integrates; you replay the integrated application, not only your isolated branch.

Prior no-push/publication restrictions are not removed by this handoff. Do not create remote issues, PRs, messages, paid subscriptions or a deployment without authorisation. Preserve true pre-event preparation and event development provenance. Official brief/reuse rules govern; old PDFs are reference, not proof of eligible work.

Target milestones: by H2 stable typed fixtures and page/file/mic capability check; H5 real source/claim/confirm/run/evidence path; H9 visible challenger and synthetic reveal plus first actual NBA run; H14 connected read-only book data, truthful unavailable/blocked comparisons and implemented voice interaction; H18 freeze features; H20 independent replay/rehearsal/export; aim for H23 submission with one hour for genuine upload/access problems. These are intended gates, not completed results.

If blocked, build against explicit local deterministic fixtures and label them as such, then replace them with real integrated responses when ready. Do not claim integration until that happens. Prefer a coherent interactive research workspace over separate marketing pages. Avoid adding a native shell or extra framework solely because it looks impressive.

## 09 / A demo that earns its claims

Adjust to the organiser's time limit; proposed four minutes. Open with one spoken NBA claim and show its exact interpretation. Attach a selected source/file and preview provenance. Let the user correct a number; the old confirmation visibly invalidates. Confirm and run the actual research loop.

Show a synthetic false discovery challenged, then a detectable planted effect that survives the frozen protocol. Reveal truth only after the decisions. If demonstrating recorded runs, label them recorded. Do not prewrite that a specific real player's claim must be accepted or rejected. The true outcome of the implemented tests determines the story.

Show held-out generator diagnostics with actual sample counts, power and uncertainty; explain simulation scope. Then show an actual NBA finding with its limitations and an independently checked numerical fixture. If available, compare one supported game forecast with a market; otherwise show the legitimate unavailable state rather than an invented probability.

For market context, show one correctly matched NBA forecast and quote, then a regulation/overtime or postponed-game mismatch that is rejected. A synthetic quote fixture proves normalisation; a live fetch demonstrates connector behaviour. Neither establishes profitable trading. Keep the central discovery/challenge/replay story in the foreground.

Close on the research benefit actually demonstrated: the agent can test its own ideas, identify an explanation that fails, preserve failures and show what data would resolve uncertainty. Do not say '90% correct in the NBA', 'risk free', 'guaranteed alpha' or 'all venues' without the corresponding evidence. No sponsor weights or winning odds are invented.

Possible expansions after core acceptance: genuinely live page/game event reactions; a native selected-file bridge; posterior talent explorer; broader validated data/venue adapters; validated dynamic talent; measured learned attack selection. Each has a named dependency/evaluation, not an unbounded promise.
