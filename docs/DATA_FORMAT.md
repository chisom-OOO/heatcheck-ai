# Shared data format: heatcheck-records/1

Owner: Max (contracts). Protocol: `heatcheck-nba/1`. Frozen 7 November 2026 as the
format that Research and Experience both produce and consume. Executable definition:
`heatcheck/contracts/records.py` (records) and `heatcheck/contracts/bundle.py`
(bundle directories). If this text and the code disagree, the code governs. Report
the disagreement to Max as a defect.

To change a field, open a request in `docs/tasks/README.md` § Schema change requests.
Do not edit `heatcheck/contracts/` on a Research or Experience branch. Max makes the
change, bumps the format version if it breaks old bundles, and regenerates the
reference bundle.

## 1. Bundle layout

```
<bundle>/manifest.json            canonical JSON + "\n"
<bundle>/records.jsonl            canonical records, sorted, one per line
<bundle>/raw/<sha256>.<ext>       raw payloads that may be redistributed
```

Validate any bundle offline with no network access:

```powershell
uv run python -m heatcheck.contracts.bundle <bundle_dir>
```

Exit code 0 prints `PASS <dir>: ... records_sha256=<hex>`. Any defect prints `FAIL` and exits 1.

Reference example (SYNTHETIC, invented values): `tests/fixtures/contracts/syn_reference_bundle/`.
It is regenerated by `tools/make_reference_bundle.py` and checked with `--check`.

## 2. Encoding rules

- **Canonical JSON**: UTF-8, keys sorted, separators `,` and `:` with no whitespace,
  no `NaN`/`Infinity`, no duplicate keys. Hashes are SHA-256 lowercase hex over exact bytes.
- **Timestamps**: UTC only, `YYYY-MM-DDTHH:MM:SS[.ffffff]Z`. Compare them with
  `records.parse_utc`, not as strings. Lexical comparison is wrong for fractional seconds;
  the validator originally had this bug.
- **Prices and quantities**: decimal *strings* (`"0.5300"`, `"12"`). Prices are in
  `PROBABILITY_DOLLARS`, meaning 0 to 1 dollars per 1-dollar contract. Cents (`"53"`) are rejected
  as greater than 1. Convert venue units in the adapter and keep the raw payload.
- **Statistics and features**: finite JSON numbers. A missing value is `null` and must have a
  `missing_reason`. Zero never stands in for a missing value.
- **IDs**: `nba:<id>`, `nba-team:<id>` and `nba-player:<id>` for real NBA identities. Use the NBA
  10-digit game id, e.g. `nba:0022300061`, and NBA team/person ids. `syn:`, `syn-team:` and
  `syn-player:` are for invented data. The namespace must match `data_mode`: synthetic ids cannot
  appear in real records, and real ids cannot appear in synthetic ones.
- **Line endings**: bundles are exempt from Git EOL conversion (`.gitattributes`). A CRLF
  checkout fails validation instead of silently changing hashes.

## 3. Record envelope

Every line in `records.jsonl` is:

```json
{"body":{...},"data_mode":"...","format_version":"heatcheck-records/1",
 "protocol_version":"heatcheck-nba/1","record_id":"...","record_type":"..."}
```

Unknown fields are rejected at every level. `data_mode` is one of `REAL_NBA_RETROSPECTIVE`,
`SYNTHETIC`, `LIVE_MARKET` or `RECORDED_MARKET`. NBA record types allow
`REAL_NBA_RETROSPECTIVE`/`SYNTHETIC`. Market record types allow `LIVE_MARKET`/`RECORDED_MARKET`/`SYNTHETIC`.

| record_type | Producer | Key body fields | Rules beyond types |
|---|---|---|---|
| `RAW_SNAPSHOT` | both | `snapshot_sha256` (= record_id), provider, source (repo@commit/path or endpoint, never a key), `redacted_params`, `retrieved_utc`, `byte_count`, `rights_note`, `bundle_path` | `bundle_path` null means not redistributed. Otherwise the file under `raw/` must match its hash and byte count. |
| `GAME` | Research | `game_id` (= record_id), season `2023-24`, competition, provider_ids, home/away team ids, `scheduled_tip_utc`, status | Home and away differ. **No final score here.** The score is a label. It is allowed in every data mode. A market-mode GAME is a schedule reference, and EVENT/FEATURE_ROW/LABEL records must share their game's NBA data mode. |
| `EVENT` | Research | game_id, provider, provider_event_id, `revision`≥1, period, `sequence` (provider order), `clock_seconds_remaining`, team/player, action, `shot` | `shot` is present if and only if `action == SHOT`. FG is worth 2/3 and FT is worth 1. `assisted_post_outcome` is post-outcome. |
| `FEATURE_ROW` | Research | target_id, `target_kind` (`PRE_SHOT_MAKE`/`PRE_TIP_TEAM_WIN`), cutoff, feature_version, features `{name:{value,missing_reason}}`, `max_input_sequence`, availability_assumption, `source_record_hashes` | Inputs are strictly before the cutoff. No feature name containing `assist`. Exactly one of value/missing_reason is set. |
| `RESTRICTED_LABEL` | Research → Custodian | target_id, `label_kind` (`GAME_FINAL_SCORE`/`TEAM_WIN`/`SHOT_MADE`), value, revision, `reconciliation` (`RECONCILED`/`UNVERIFIED`/`QUARANTINED`) | The value keys must exactly match the kind. |
| `VENUE_MARKET` | Experience | venue, venue_api_version, event_id, market_id, title, outcomes `[{contract_id,label}]`, rules_text_sha256, price/quantity unit, tick_size | Outcome order carries no meaning. Never assume that the first outcome is YES. |
| `VENUE_MAPPING` | Experience proposes, Max verifies | mapping_id, game_id, venue_market_record_id, contract_id, team_id, `outcome_direction`, `overtime_convention`, cancel/postpone, `status` | contract_id belongs to that market. team_id plays in that game. `VERIFIED` needs a known overtime rule. |
| `QUOTE` | Experience | mapping_id, venue, market_id, contract_id, `levels [{side,price,size,derivation}]`, provider_time, `fetch_start_utc`, `received_utc`, adapter_version, `status`, raw_snapshot_id | received ≥ fetch start. An `OK` quote has levels and is not crossed. A non-OK quote has a reason. Levels are stored as the venue gave them (`DIRECT`). Derived complements are Research's normaliser output. Midpoint and last trade are never stored as a level. |

Record id conventions (recommended; uniqueness per type is enforced):
`EVENT` `<game_id>:<provider_event_id>:r<revision>`, `FEATURE_ROW`
`<target_id>:<feature_version>`, `RESTRICTED_LABEL` `<target_id>:r<revision>`,
`VENUE_MARKET` `<VENUE>:<market_id>`, `QUOTE` `quote:<mapping_id>:<raw sha[:16]>`.

## 4. Manifest

Exactly these fields: `protocol_version`, `format_version`, `bundle_id`,
`created_by_role` (`MAX`/`RESEARCH`/`EXPERIENCE`), `created_utc`,
`producer {tool, version, ...}`, `records_sha256`, `record_counts`, `data_modes`,
`exclusions [{id, reason}]` and `notes`. Build it with `bundle.build_manifest`. Do not build it by hand.

## 5. What validation does and does not prove

`PASS` proves structure, units, id namespaces, internal references and byte integrity
for that bundle. It does not prove that the data are correct NBA facts, that a feature
builder is leak-free beyond the declared cutoff fields, that a mapping is semantically
right or that a quote was live. Those are separate gates (G01, G02, G10–G12 in
`ACCEPTANCE.json`).

Where data live: real NBA bundles go in `data/bundles/` and are git-ignored because raw
redistribution rights are unverified. Commit the fetch manifest, the `records_sha256` and
reports. Small fixtures whose rights note permits redistribution go in `tests/fixtures/`.
