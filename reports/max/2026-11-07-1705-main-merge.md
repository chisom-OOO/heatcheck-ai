## Does Experience's UI conflict with my evidence ledger format?

**Yes, at the field level. The verdict vocabulary agrees.**

Experience built `web/referee.js` against a **provisional** shape, `provisional-experience/0`,
because my record format had not been delivered. If a ledger entry is opened in the UI as it
stands, it renders as mostly "unavailable", with a long gaps list. It does not crash: the
view model never throws and never zero-fills.

| UI expects (`provisional-experience/0`) | Ledger entry has (`heatcheck/ledger/evidence.py`, `loop.py`) | Conflict |
|---|---|---|
| top-level `format` | none (`identity.protocol_version = heatcheck-nba/1`, `registry_version`) | UI flags "format … is not provisional-experience/0" |
| top-level `data_mode` | `identity.data.data_mode` (and per attack `scope.data_mode`) | path |
| `claim.claim_id` | `identity.claim.claim_id` | path only |
| `claim.statement` | `identity.claim.plan.statement` | path |
| `claim.plan_hash` | `identity.claim.canonical_plan_hash` | name |
| `claim.revision` | none; `identity.claim.version` is the registry version, not a user revision | **semantic**: registered claims have no user revision yet |
| `attacks_run[].test_id` | `attack_results[].test_id_version` (`A-…@1`) | name/format |
| `attacks_run[].outcome` ∈ PASSED/FAILED/NOT_RUN/ERROR | `attack_results[].status` ∈ EXECUTED/FAILED/… | **semantic**: my status says whether the test *ran*. Whether it "passed" is only decided by the Referee over all attacks, so no per-attack PASSED exists. |
| `attacks_run[].statistic`, `p_value`, `reason` | same names | OK |
| `attacks_run[].method` | `null_method_assumptions` | name |
| `verdict.decision`, `verdict.reason` | `identity.decision`, `identity.reason` | path only |
| verdict enum SURVIVED_PROTOCOL / NOT_SUPPORTED / INSUFFICIENT_EVIDENCE / DATA_INVALID / BLOCKED | identical five values | **OK** |
| `evidence[] {label, value, kind}` | none as a list. The hashes are spread over `evidence_id`, `entry_hash`, `identity.code`, `identity.data`, `attack_results[].evidence_hash` | missing |
| not present | `evidence_id`, `created_at_utc`, `proposer`/`challenger`/`referee` identities, `limits`, `channel` | UI would not show them |

**Resolution (Max owns the format):**
- I will not rename ledger fields. The ledger identity is hashed, and renaming would change
  every evidence id.
- I will publish a **read-only projection** `heatcheck-referee-view/1`, derived from a ledger
  entry, plus its fixture. Experience then changes only `fromRecord()`, as their report already
  anticipates.
- The outcome semantics need agreement: I propose showing `status` as supplied
  (EXECUTED / NOT_EXECUTABLE / FAILED) rather than inventing PASSED.
- The dialogue endpoint (next report) returns `evidence_record_id` and `verdict` using the same
  five decision values.
