## 2. One-command demo on Windows

**Command,** in the repository root: `.\demo.cmd`. This is the same as `uv run --frozen --group research python tools/demo.py`. It is documented in README under "Run the demo (Windows)".

What it does:
1. **Fetch and verify the data (first run only).**
   - It downloads the three pinned archives from `shufinskiy/nba_data@46488f0f`, about 46 MB.
   - It checks each against Research's `SHA256SUMS` and stops on any mismatch.
   - It extracts them with `tarfile` (`filter="data"`).
2. **Build the bundle.** It runs Research's unchanged `build_dataset.py`, then `tools/bridge_r001_game.py`. It then checks that the bundle's `records_sha256` equals the data identity in the committed ledger, and refuses otherwise.
3. **Prepare the demo ledger.** It copies the committed ledger to `logs/demo/evidence.jsonl` (git-ignored).
4. **Start both servers on that ledger.** The dialogue API runs on 8770 and Experience's UI on 8765. It opens both in the browser. Ctrl+C stops both.
   - It uses live model calls when `META_API_KEY` is set, unless `--no-llm` is given.
   - It refuses to start if either port is already in use.

Other changes:
- The dialogue server now serves a small **console page** at `GET /`. Experience's UI does not yet send questions to `/api/dialogue`; wiring it is Experience's job.
  - The page sets text with `textContent` only.
  - It is served with a strict CSP: `connect-src 'self'`.
  - Other GET paths return 404, which is tested.
- **`.gitattributes`:** `*.cmd` is checked out with CRLF, because the repository default is LF.
- **Why `--group research`:** plain `uv run --frozen` installs only the dev group. numpy and pandas, which the UI server and Research's builder need, are in the `research` group.
