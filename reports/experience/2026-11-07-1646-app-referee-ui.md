## Item 2: fixture inconsistencies (`6820913`)

- **One unit label.** `PROBABILITY_DOLLARS` is now the only price-unit label:
  - `quotes.PRICE_UNIT` is used in `MarketSpec.price_quantity_grid`, `BookSnapshot.price_unit` and `MarketComparison.quote_type_unit.unit`.
  - `parse_price` refuses every other unit, non-string prices and values outside [0, 1].
  - Legacy Kalshi integer-cent orderbooks are now refused as `UNKNOWN_UNITS` instead of converted.
  - `source_price_unit` is removed.
  - Behaviour change: scenario `kalshi_cents_legacy` now ends `UNKNOWN_UNITS`, where it used to end `OK` with +0.04.
- **Z timestamps.** The new `server/timefmt.py` writes every timestamp as UTC with a `Z`. All `isoformat()` writers now use it, and the `+00:00` literals in `venue_fixtures.py` are gone.
- **BookSnapshot clock.**
  - Root cause: `FixtureTransport` stamped the wall clock as `received_at_utc` next to an authored `provider_time`. The old file had 15:42Z received against 23:58Z provider time.
  - Fix: fixture transports now carry an authored per-scenario clock (provider time + 1 s). `BookSnapshot.json` now reads `provider_time 2026-11-07T23:58:00Z`, `received_at_utc 2026-11-07T23:58:01Z`.
  - Guard: `_snapshot` refuses any `provider_time` more than 5 s after receipt, with status `CLOCK_SKEW`. A new scenario, `kalshi_clock_skew`, reproduces the old defect and is refused.
- **Polymarket tokens.** `clobTokenIds` is now preferred, as verified on the real v1 capture. `positionIds` is kept only as an unverified v2 fallback, and the fixture market now uses the v1 shape.
- **Regeneration and tests.**
  - Fixtures were regenerated with `uv run python tools/build_fixtures.py` from `apps/web`.
  - New tests cover:
    - unit refusals;
    - Z format;
    - the clock guard, including the within-tolerance case;
    - `provider_time <= received_at_utc` for every fixture scenario;
    - the committed envelopes: no `+00:00`, one unit label, clock order.

## Item 3: Referee evidence view (`5919c1c`)

- **Status.** The format is **provisional**: Max has not delivered the record format yet. Every view says so on screen.
- **`web/referee.js`.** A pure view model (no DOM, no network, no statistics) with four parts: claim, attacks run, verdict and evidence.
  - `fromRecord()` reads a `provisional-experience/0` record.
  - `fromStandInRun()` maps today's stand-in engine run into the same view and labels it "Stand-in engine output, not a Referee record".
  - Values are shown exactly as supplied. Missing values show as "unavailable: reason" and are listed under "Gaps in this record".
  - Unknown verdicts and outcomes are shown raw and flagged, never mapped to a known state.
  - A mandatory attack the engine did not report appears as `NOT_RUN`.
- **Decision card.**
  - Step 6 is now "Referee evidence record". Its sections are claim, attacks run, verdict, evidence and gaps.
  - A new "Open a Referee record (JSON)" control renders a file through the same view, so the screen can show Max's record by changing only `fromRecord()`.
  - The talent chart moved under "Stand-in engine extras (not part of a Referee record)".
  - A run only shows the claim whose plan hash matches it, never another revision's claim.
- **Example record.** `fixtures/referee/provisional_record.example.json` is an authored example, not Referee output.
