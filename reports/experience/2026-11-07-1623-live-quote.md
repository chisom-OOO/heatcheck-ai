## Real payloads vs the earlier authored assumptions

These are findings, not failures:

1. **Polymarket is `version: "v1"`.** Outcome tokens are in `clobTokenIds` (a JSON string). The
   payload also has a `positionIds` array, but those are different ids. The old ZIP fixture's
   `v2`/`positionIds` shape is therefore **unverified** against any real payload. The token
   chosen from `clobTokenIds` matched the book's `asset_id`.
2. **Kalshi `no_sub_title` repeats the YES subject.** It says "Indiana", not what NO means.
   Fixed: the NO outcome is now labelled `NO`. Before this, the label would have read
   `NO (Indiana)`, which is misleading.
3. **Kalshi has no `tick_size_dollars`.** It gives `price_level_structure: linear_cent` and a
   single `price_ranges` step of `0.0100`. The adapter now reads the tick from that single step.
4. **Kalshi rules do not mention overtime,** so `overtime_convention` is `UNKNOWN`. Polymarket
   rules say "including any overtime periods", so it reads `INCLUDES_OVERTIME`. A VERIFIED
   Kalshi mapping would need a rules source that states overtime.
5. **Kalshi `occurrence_datetime` and `expected_expiration_time` are 2026-11-08T01:00:00Z.**
   That is not the tip time (22:00Z), so it must not be used as tip.
6. **Kalshi `orderbook_fp` has `yes_dollars`/`no_dollars` bid ladders in 4-decimal dollar
   strings,** as the earlier adapter assumed.
