## What changed

1. **Pass-through, no CORS** (`apps/web/server/app.py`).
   - Max's endpoints `/api/dialogue`, `/api/investigate`, `/api/live-forecast` and `/api/display-titles` are forwarded to Max's dialogue server. Method, body, status and `Content-Type` are unchanged.
   - The target is `--api`, default `http://127.0.0.1:8770`. It must be loopback; anything else is refused at start-up and per request.
   - When Max's server does not answer: `502 {"error":"UPSTREAM_UNAVAILABLE"}`.
   - Same-origin POSTs only (the existing Origin check). The browser's `Origin` is not passed on.
   - CSP is now `connect-src 'self'`.
2. **The demo page calls relative URLs only.**
   - `demo.js` and `market/board.js` use `/api/...`. The `?dialogue=` override is gone.
   - The page works on any port.
   - Dialogue timeout is 30 s, per `docs/DIALOGUE_API.md`.
3. **`/` opens `demo.html`.** The older workspace UI is still at `/index.html`. `tools/demo.py` already opens `/demo.html`.
4. **Market board** (the "Tonight's games" button, or `demo.html?board=1`).
   - One card per game in `/api/live-forecast`. Each card shows:
     - the forecast,
     - Polymarket bid and ask,
     - the difference,
     - the forecast data cutoff,
     - the time the price was received,
     - the inputs used.
   - When that is the answer, the card says **SAMPLE** or **Can't compare** plainly, with the failed checks in plain words.
   - "Ask Heater about this game" plays Heater's line, then the Ref, then the stamp: SAMPLE, CAN'T COMPARE or EDGE UNVERIFIED.
   - Heater's line shows input names in plain words (e.g. "Elo rating (home)", not `elo_rating_home`).
   - Every number comes from Max's `/api/investigate`. The board never computes a verdict.
   - Bids-only Kalshi books are never chosen.
   - Each game is investigated once per page view, and each call adds one entry to Max's investigation ledger.
5. **`/api/market-mappings`.**
   - Serves the newest `data/experience/quotes/*/board.mappings.json`, or `--quote-index`.
   - Contains ids, labels and capture statuses only, no prices.
   - With no flag needed, it works with Max's `demo.py` (6a78318).
6. **"Do home teams win more?"**
   - Max's API answers CONF-HA SURVIVED_PROTOCOL, lane CONFIRMATORY, evidence `b81af39a…`, which is in the committed `evidence/evidence.jsonl`.
   - The page shows the **vindicated** pose and the **SURVIVED** stamp.
   - The Ref says: "Home teams won 54.5% of their games, tested on a season the system had never seen", then "1,224 games in 2024-25, p = 0.005" (Holm p).
   - Every number is read from the ledger record.
7. **Fix:** `isLedgerEntry` (heater-model.js) refused recorded Research finals, which have a lane and a result but no `attack_results`. The new test found it. The live path (`/api/evidence`) was not affected; the offline JSONL fallback was.
8. **`heatcheck/markets/live_quotes.py`.**
   - The validator now matches Max's `live_forecast` rules:
     - the label is exactly "DESCRIPTIVE FORECAST";
     - SAMPLE is decided by `source.results`;
     - a SAMPLE may use the literal `SAMPLE` in `fetched_utc` and `sha256`;
     - the `cross_check` rule applies.
   - Max's own validator also runs when it is present.
   - `capture` now writes `board.mappings.json` (also `index <run_dir>`).
   - No merged bundle: Max's server reads the per-contract bundles under `data/experience/quotes`.
   - `tests/fixtures/live/forecasts.SAMPLE.json` was updated to Max's literal rules and still says SAMPLE. The committed capture's `quotes.json` records the sha256 of the previous version of that file (in 0d92d55).
