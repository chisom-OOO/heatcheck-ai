## What it does

- **Button visibility:**
  - A red "Corrupt one byte" button sits in the top bar.
  - Max's endpoint landed before 08:45, so it **shows by default**.
  - `?tamper=0` hides it.
  - `?tamper=mock` runs on in-page replies in Max's shape. Every text value says MOCK, and the panel says "MOCK REPLY: no request was sent and no file was changed".
- **Click sequence:**
  1. The Ref card shows "Checking the seal".
  2. The page sends `POST /api/tamper/flip`.
  3. The panel shows the file, line, offset, expected, actual and validator error. "File" is a fixed label, "evidence/evidence.jsonl (scratch copy; the committed file is only read)", taken from Max's doc; his reply has no file field.
  4. The page sends `GET /api/tamper/events`. The new row is the TAMPER_ATTEMPT event whose `evidence_id` equals the flip's `ledger_event_id`. It is marked and shown under up to 3 earlier events, with a heading naming the ledger (`logs/tamper_events.jsonl`). If the events list doesn't load or lacks the row, the panel says so; nothing is invented.
  5. The Ref speaks the personality's DATA_INVALID line with the validator's own message: "No ruling. The data failed its checks: ledger line 5: identity hash mismatch (tampered)."
  6. The **DATA INVALID** stamp lands, but only when the reply says `verdict: DATA_INVALID`.
  7. Heater takes the blocked pose and gives his DATA_INVALID reaction.
- **Restore:**
  - After a flip, a "Restore the byte" button appears. It sends `POST /api/tamper/restore`.
  - The status line then says the corrupted copy was deleted and that the committed ledger was only read and never changed.
  - Corrupt stays disabled until Restore succeeds, so only one flip is out at a time.
- **Errors:**

  | Reply | What the panel shows |
  |---|---|
  | 429 `RATE_LIMITED` | "one flip per 5 seconds; wait a moment and try again" |
  | 503 `TAMPER_OFF` | "the tamper demo is off on this server" |
  | 500 `NOT_DETECTED` | "CHECK FAILED: … THE LEDGER READER ACCEPTED THE TAMPERED COPY", in a red alarm box, with a **CHECK FAILED** stamp. The Ref says not to trust a ruling until it's fixed. |
  | A missing route, network error or non-JSON reply | "Nothing was flipped: …", with no values and no stamp |

  NOT_DETECTED is never shown as a pass.
