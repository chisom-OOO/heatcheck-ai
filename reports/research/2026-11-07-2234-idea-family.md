## What was built

1. **Grammar** (`docs/IDEA_GRAMMAR.md`): two templates with enumerated string parameters only.
   - `GAME_HOME_WIN_SPLIT`: features are rest days (home/away), rest advantage, back-to-back (home/away),
     Elo gap bucket, month and day of week.
   - `SHOT_MAKE_AFTER_CONDITION`: conditions are after 1–4 makes, after 1–4 misses, shot value and period.
   - Anything else is refused: an extra key, a non-string, whitespace, case, an unknown level, a duplicate
     idea, more than 20 ideas, NaN or duplicate JSON keys.
2. **Tests** (`heatcheck/ideas.py`). Both templates are permutation tests reusing the kernels (`permute_within`,
   `holm`), B = 999, with a seed derived from the idea's hash.
   - GAME: home results are shuffled across eligible games.
   - SHOT: outcomes are shuffled within player × game × shot value (player × game for the shot-value
     condition). Streak conditions are recomputed after every shuffle.
   - Minimum samples: 30 games or 200 shots on each side.
3. **Family** (`run_family`):
   - It validates the whole request, then writes `registration.json` **before computing**. The file is
     write-once and holds every idea hash, the data identity, the code hash, B, α and the seed rule.
   - It re-reads and verifies the registration before computing.
   - It runs every idea, applies Holm across **all N** (an idea without a p-value counts as p = 1), and
     writes `results.json` (write-once).
   - Verdicts are `CANDIDATE` / `NOT_A_CANDIDATE` / `INSUFFICIENT_EVIDENCE`, never `SURVIVED_PROTOCOL`.
4. **Data scope.**
   - Development mode accepts only the 2023-24 build and only its 930 development games. The development
     view checks that it contains no spent final game. The loader refuses the 2024-25 build (tested).
   - No code path in the module reads the sealed season or the custodian ledger.
5. **Synthetic mode.**
   - It runs a planted-truth league from `simulate.generate`, plus random period labels from a separate
     stream, which are planted nulls.
   - The family receives only the view: outcomes, player-game ids, shot values, periods.
   - `truth.json` is written after `results.json`, carrying that file's sha256. `scoreboard.json` joins the
     two.

How to read it:
- **Both positive controls were found.** Back-to-back and rest gaps of about 5–6 points did not survive
  Holm over 12 ideas.
- **No streak idea came close**, consistent with D11.
- **The two period candidates are exploratory associations, not explanations.** Relative to the
  within-player-game shuffle, shots in the 4th quarter go in less often and shots in the 1st quarter more
  often than expected. The test does not control shot difficulty within a shot value: end-of-quarter heaves,
  late-game defence and garbage time all could produce this.
- **A CANDIDATE is not a claim.** It needs its own pre-registration and a sealed confirmatory test, and the
  2024-25 seal is already closed to new families.

### Synthetic scoreboards (13 SHOT ideas each)

Source: `evidence/idea-family/synthetic_*/{results,truth,scoreboard}.json`. Runtime about 23 s each.
League parameters were fixed in `RUN_PLAN.md` before running.

| League (revealed after results) | Shots | Planted effects found | Missed | Nulls correctly not flagged | False candidates |
|---|---|---|---|---|---|
| Family A, γ = 0.30, seed 20261108 | 12,024 | **1** of 9 | 8 | **4** of 4 | **0** |
| Family A, γ = 0 (control), seed 20261109 | 11,989 | **1** of 1 | 0 | **12** of 12 | **0** |

**What this shows (one league each, so these are counts, not rates):**
- **No false candidates** in 16 null ideas across both leagues.
  - In the control league, two period ideas had raw p 0.052 and 0.017. Holm removed them (0.572, 0.204).
- **The planted streak effect was missed.**
  - The directly planted idea (after 3 makes, greater) had raw p 0.020. Holm across 13 ideas raised it to
    0.240.
  - The only effect found in the γ = 0.30 league was the large built-in 3-point difference.
- **This is a real limit of the machine as built:**
  1. **Multiplicity:** Holm across 13 ideas needs raw p < 0.0038 for the strongest idea.
  2. **Estimand:** "condition vs all other eligible shots" is a weaker contrast than the harness's "after 3
     makes vs after 3 misses", which reached 0.87 power at γ = 0.30 for a single test.
  3. **League size:** about 12,000 shots, against 165,710 in the real development data.

  More ideas per family means fewer planted effects found. A proposer should send few, focused ideas.
- **The truth table counts overlap effects as planted** (after 1/2/4 makes, after misses). These follow
  from the k = 3 term but may be very small, so "8 missed" overstates what was realistically findable. Only
  one effect, k = 3, is planted directly.

## Limits and notes

- **Truth separation in the synthetic demo is enforced in code only.** The views carry no truth, and the
  truth file follows the results. But Research wrote both the requests and the league choice. Real
  separation starts when Max's proposer emits requests without seeing the runner's choice.
- **GAME ideas assume games are exchangeable.** Within-day and within-team dependence is not modelled.
  SHOT ideas test association under within-stratum exchangeability, not cause.
- **`docs/IDEA_GRAMMAR.md` §6 differs slightly from the code in one detail:** `run_family` takes a mapping
  `views = {template: view}` rather than a single view. The code governs, as the grammar says. The
  proposer-facing grammar (§1–§5) is unchanged.
- **Live forecast:** dropped on instruction, so no forecast file or BALLDONTLIE work was done.
