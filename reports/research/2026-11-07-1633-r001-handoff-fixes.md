## Fix 2: LF line endings

`pandas.to_csv` uses `os.linesep` when no `lineterminator` is given. `Path.write_text` translates `\n` on
Windows. Changes (commit `6c732d4`, 2 files, 5 lines):

| File | Call | Change |
|---|---|---|
| `scripts/build_dataset.py` | `rec.to_csv(... reconciliation_2023.csv)` | `lineterminator="\n"` |
| `scripts/build_dataset.py` | `manifest.json` `write_text` | `newline="\n"` |
| `scripts/shot_association.py` | `df.to_csv(... harness_league_results.csv)` | `lineterminator="\n"` |
| `scripts/shot_association.py` | `harness_report.json`, `hot_hand_dev.json` `write_text` | `newline="\n"` |

The `write_text` changes go one step beyond the literal request. Without them the JSON outputs
are still CRLF on Windows. `util.frame_hash` and `features.feature_bytes` already used LF.

**Deliberately not changed:** `scripts/game_prediction.py`. It is in `CODE_FILES`, so editing it changes the
frozen GAME_PREDICTION `code_hash` (`d496e34e…`), and the final replay would then refuse to run ("code
changed since freeze"). Its three `write_text` JSON outputs (`game_prediction_dev.json`,
`claim_plan_GP.json`, `game_prediction_final.json`) **remain CRLF on Windows**. This is a known limitation.
Changing it needs a new plan/epoch decision by Max.

## Fix 3: known weaknesses in the pre-shot invariance test

`handoff/research-20261107/tests/test_time_integrity.py::test_preshot_future_perturbation_invariance`:

- **Covers one target shot, not every shot.** It picks the middle FGA of the first game. It flips that shot
  *and every later shot* in the game, corrupts later scores and sets assist/block/descriptor on the
  target. Invariance is then asserted only for rows up to that target. So exactly **1 of 181** shots in
  the game is checked against a flip of its own outcome (1 of 3,601 FGA rows built). R-001 A4 requires
  every shot.
- **Downstream check can pass vacuously.** The sensitivity assertion (line 115) sits inside
  `if len(nxt):`. If the target shooter has no later shot, nothing is asserted. In this replay the
  branch **did** execute (5 later shots by player 1629060, game `0022300061`, target sequence `3012500`),
  but 19 of the 181 shots in that game would have made it vacuous (`logs/a4_probe.log`).
  Because every later shot is also flipped, this check is weaker than A6 intends.
- **Additional point:** the file's leaky negative control (`_leaky_season_rate`) is a *pre-game* feature.
  There is no deliberately leaky *pre-shot* builder, so A5 is not covered for pre-shot features.

Per Max, the reviewer covers this with a separate harness (`review/independent-tests`,
`tests/review/test_rv_preshot_invariance.py`). I did not change the test.
